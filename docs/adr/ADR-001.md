# ADR-001 — Reference language: Python stdlib now, Go for production

**Status:** Accepted · **Date:** 2026-09-02 · **Deciders:** principal engineer + author

## Context
The team wanted Go (throughput, deployment simplicity, safety). The build sandbox has a restrictive
network egress allowlist (verified): GitHub API/codeload, npm and PyPI are reachable; Go download
CDN, module proxies, container registries and distro mirrors are not. Without the toolchain or the
module proxy, a Go implementation could not be compiled or tested here. We refuse to ship
unverified code as "production-grade".

## Decision
- Ship the reference implementation in **Python 3.11, standard library only** — zero third-party
  runtime dependencies, fully tested in this environment (unit, concurrency, chaos).
- Keep the architecture **hexagonal** so the Go port is a mechanical translation.
- Provide `docs/10-go-porting-blueprint.md` (module-by-module mapping) and a CI gate
  (`.github/workflows/ci.yml`) that builds and tests the Go port on push, where the network is normal.

## Consequences
+ Verified code, reproducible, runnable today; zero supply-chain surface.
+ Python 3.11 stdlib + SQLite gives us the same correctness invariants to test.
− Runtime throughput ceiling lower than Go (still ≥2k ops/s per core at p95 < 25 ms; the
  measured NFRs hold).
− Production teams may prefer Go; the port path is documented and CI-gated, not speculative.

## Revisit triggers
Go toolchain available in the build environment → port the store/API adapters (domain is unchanged),
flip CI gate to primary.
