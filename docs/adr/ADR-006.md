# ADR-006 — External workers: pull-based claims with fencing tokens

**Status:** Accepted · **Date:** 2026-10-01

## Context
The kernel scheduled lease-bound workflow nodes but only its own event nodes could complete
themselves. A real worker (an agent runtime, a container, a remote executor) had **no way to
discover work** and no safe way to prove it still owned an attempt: attempt ids were internal and
`POST /attempts/{aid}/complete` accepted any writer that knew an id. Effect: the compute plane
could not actually be driven from outside the process, and the API surface silently trusted
possession of an opaque id.

## Decision
Expose the executor protocol as a first-class, pull-based API:

- **Discover** — `GET /v1/attempts?claimable=true&state=running` returns lease-bound, unclaimed,
  running attempts *namespace-scoped*, with the node name, workflow name and deadline.
- **Claim** — `POST /v1/attempts/{aid}/claim {worker_id, ttl_seconds}` binds the worker to the
  attempt and **takes over the attempt's lease slot** (holder = worker, fresh nonce, renewed
  expiry). Returns the fencing `nonce` and the `deadline`.
- **Heartbeat** — `POST /v1/attempts/{aid}/heartbeat {worker_id, nonce, ttl_seconds}` renews the
  lease through `Lease.renew` (nonce compare + stale-expiry guard).
- **Complete** — `POST /v1/attempts/{aid}/complete` now requires the namespace *and*, for claimed
  attempts, the live nonce. A worker that was fenced out gets `409 conflict`; it can never write
  a result for work it no longer owns. Results are bounded (64 KiB) and recorded on the attempt.
- **Reclaim** — the kernel fails attempts whose lease expired (`lease_expired`) so retry policy
  applies, and the scheduler reaps expired leases (`lease.expired`) so capacity accounting stays
  honest and local state stays bounded.

Claiming is *at-most-one live owner, at-least-once execution*: leases bound how long an owner is
believed, retries bound how often work is re-dispatched, and the nonce is the fence that makes an
old owner harmless.

## Consequences
+ Any process — in any language — can now be a worker; SAF's `saf worker` is the first client.
+ A stalled worker cannot double-complete: re-claiming rotates the token and fences the old copy.
+ Cross-tenant attempt access is a 404; the id is no longer a capability.
+ Deadline ownership moves to the worker (heartbeat), which is where liveness actually lives.
− Claim/heartbeat add two round-trips per attempt; a bad worker can now hold a slot for its TTL
  (bounded by `ttl_seconds` ≤ 3600 and the node timeout).
− Unclaimed lease-bound attempts still wait for a worker: dispatch is *pull*, so "no worker" looks
  like "no progress" until node/workflow timeouts fire (visible in `/v1/attempts`).

## Revisit triggers
Push-based dispatch (server → worker channels) when worker fleets get large enough that polling
cost matters; multi-node kernel (ADR-004/002) makes claims a cross-node read-modify-write, which
requires the Postgres adapter's row locks rather than the single-writer lock.
