# ADR-004 — Leadership: lease-based single writer (no embedded consensus in v1)

**Status:** Accepted · **Date:** 2026-09-02

## Context
The store is single-writer. If we ever run two kernel processes against one store (HA, rolling
restart), we need mutually exclusive leadership without dragging in a consensus library.

## Decision
- **Lease leader:** `leader` row = `{holder_id, nonce, expires_at}`; heartbeat extends
  *if-holder-and-nonce-match*; TTL 5 s default, heartbeat 1 s.
- Demotion is clean: on `renew_ok=False`, loops stop acting, close store, exit `LEADER_LOST`.
- All writes are **epoch-scoped** (leader nonce embedded in a header) — a stale writer's changes
  are rejected, making the worst case "no writes momentarily", never corruption.
- v2 adapter surfaces: Postgres advisory lock or embedded consensus (same `LeaderElection` port).

## Consequences
+ Zero dependency; split-brain window bounded by TTL and epoch check; rolling restart is safe.
− Not a distributed consensus system; failover is restart/retry-based (documented).

## Revisit triggers
Multiple kernel processes in production for >1 month, or strict RPO/RTO requiring automated
failover < 1 s.
